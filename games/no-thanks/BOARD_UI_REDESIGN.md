# No Thanks! 보드 UI 개편 요구사항 — 2026-09-22

> 실제 브라우저 수동 QA 이후 확정된 No Thanks! 보드/좌석/개인 패널 UI 개편 요구사항을 다음 채팅에서 바로 구현할 수 있도록 정리한 기준 문서입니다.
>
> 게임 규칙, 서버 권위, DB/RPC, reconnect 정책은 기존 GAME_SPEC.md, DEVELOPMENT.md, RELEASE_CHECKLIST.md를 그대로 따릅니다. 이번 문서는 화면 구조와 UX 개편만 다룹니다.

## 1. 개편 목표

현재 No Thanks! 화면은 기능적으로 게임 상태를 확인할 수 있지만 실제 보드게임을 하는 듯한 몰입감이 부족합니다.

이번 개편의 핵심 목표는 다음과 같습니다.

1. 게임 화면의 중심을 대형 보드판으로 바꿉니다.
2. 보드판 안에 원형/타원형 게임 테이블을 두고 3~7명의 플레이어를 둘레에 배치합니다.
3. 각 사용자의 화면에서 본인 좌석은 항상 6시 방향에 고정합니다.
4. WAITING 상태부터 실제 게임 테이블을 보여주고 준비된 플레이어가 자리를 채우는 경험을 제공합니다.
5. 플레이어 좌석은 최대한 간결하게 유지합니다.
6. 개인 정보와 실제 조작은 보드판 아래의 개인 패널에 집중합니다.
7. 카드와 칩은 실제 보드게임 감성을 주되 화면이 지저분해지지 않도록 정리합니다.
8. 테이블 위 오브젝트는 향후 애니메이션 이벤트가 자연스럽게 연결될 수 있도록 설계합니다.
9. 핵심 플레이 중에는 위아래 스크롤을 최소화합니다.

## 2. 전체 화면 구조

No Thanks!의 PLAYING 화면뿐 아니라 WAITING 화면부터 아래 공통 레이아웃을 사용합니다.

~~~
┌──────────────────────────────────────────────────────────────┐
│                       GAME BOARD                             │
│                                                              │
│              Player seat            Player seat              │
│                                                              │
│        Player seat      ╭────────────────────╮   HUD          │
│                         │                    │                 │
│                         │    ROUND TABLE     │                 │
│                         │                    │                 │
│                         │  current card      │                 │
│                         │  center chips      │                 │
│                         │  draw deck         │                 │
│                         │                    │                 │
│        Player seat      ╰────────────────────╯   Player seat   │
│                                                              │
│                            ME                                │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│                         MY PANEL                             │
│  내 칩       내 보유 카드                      내 행동        │
└──────────────────────────────────────────────────────────────┘
~~~

핵심 원칙:

- 큰 직사각형/정사각형 형태의 게임 보드판 카드 영역이 먼저 존재합니다.
- 원형 테이블은 그 보드판 안쪽의 하나의 구성 요소입니다.
- 플레이어 좌석도 원형 테이블 주변이지만 게임 보드판 영역 내부에 배치합니다.
- 보드판 바로 아래에 별도의 개인 패널을 둡니다.
- 기존처럼 우측의 큰 플레이어 현황 영역이 보드판 폭을 줄이지 않도록 합니다.

## 3. 게임 보드판 크기

현재보다 가로뿐 아니라 세로도 확실히 커져야 합니다.

데스크톱 방향:

- 브라우저 좌우 폭을 거의 전부 사용합니다.
- 공통 사이트 여백 정도만 남기고 보드판 자체에 좁은 max-width를 두지 않는 방향을 우선합니다.
- 보드판 높이는 현재보다 크게 늘립니다.
- 사용자가 보드게임 테이블 전체를 한 화면에서 바라보는 느낌을 받아야 합니다.
- 단, 보드판 + 개인 패널 때문에 매 턴마다 위아래로 스크롤해야 하는 구조는 피합니다.

데스크톱에서는 가능한 한 보드판 전체, 개인 패널, 핵심 액션 버튼을 한 화면 또는 아주 작은 스크롤 범위 안에서 확인할 수 있어야 합니다.

정확한 vh 값은 구현 중 실제 화면을 보고 조정하되, 기존보다 조금 커지는 정도가 아니라 화면의 대부분을 게임 보드판이 차지하도록 합니다.

## 4. 원형 게임 테이블

게임 보드판 중앙에 큰 원형 또는 타원형 테이블을 배치합니다.

테이블은 다음을 표현하는 공용 게임 무대입니다.

- 현재 공개 카드
- 다음 카드 더미
- 현재 카드 위에 쌓인 중앙 칩
- 현재 진행 중인 애니메이션
- 카드/칩 이동 이벤트

테이블 위에는 다음을 항상 펼쳐두지 않습니다.

- 다른 플레이어의 정확한 칩 개수
- 모든 플레이어의 보유 카드 전체 목록
- 상세 플레이어 상태 목록
- 큰 액션 버튼

테이블은 상태판이 아니라 실제 게임 진행이 일어나는 공간으로 유지합니다.

## 5. 중앙 카드 / 칩 / 덱

### 현재 공개 카드

- 가장 눈에 잘 띄는 게임 오브젝트
- 현재 선택 대상이라는 점이 바로 보여야 함
- 실물 카드 느낌을 유지하되 화면 전체를 압도할 정도로 크지 않게 구성

### 카드 더미

- 다음 카드가 있다는 것을 직관적으로 보여주는 뒷면 덱
- 남은 카드 수 숫자는 별도 작은 정보로 표시 가능
- 향후 카드 공개 애니메이션 시작점으로 사용

### 중앙 칩

- 현재 카드 위에 쌓인 공개 칩
- 정확한 개수는 숫자로 보조 표시 가능
- 실제 작은 칩들이 정돈된 형태로 쌓여 있는 비주얼
- 칩은 반드시 일렬일 필요 없음
- 너무 랜덤하게 흩뿌리지 않고 정돈된 칩 더미처럼 보여야 함

## 6. 플레이어 좌석 배치

No Thanks!는 3~7인 게임이므로 고정 사각형 좌석 배치를 사용하지 않습니다.

- 3명: 테이블 둘레 균등 배치
- 4명: 테이블 둘레 균등 배치
- 5명: 테이블 둘레 균등 배치
- 6명: 테이블 둘레 균등 배치
- 7명: 테이블 둘레 균등 배치

참가 인원 수에 따라 원형 둘레 좌표를 동적으로 계산합니다.

### 본인 좌석 6시 고정

각 브라우저에서 현재 사용자의 좌석은 항상 시계 방향 기준 6시에 둡니다.

서버의 실제 turn order나 seat 정보는 바꾸지 않고 화면 표현만 회전해야 합니다.

### 좌석 흔들림 방지

- current player 강조 때문에 좌석 자체 크기가 크게 변하지 않게 합니다.
- 현재 차례는 glow / border / 작은 turn marker 등으로 표현합니다.
- turn 변경 때문에 다른 좌석이 이동하거나 레이아웃이 흔들리면 안 됩니다.

## 7. 플레이어 좌석에 표시할 정보

좌석에는 정보를 많이 넣지 않습니다.

항상 표시:

- 닉네임
- 현재 차례 여부

좌석 본체에서 제외:

- 정확한 칩 개수
- ready 상태 텍스트
- 연결 상태 텍스트
- 방장 상세 상태
- 카드 전체 목록
- 장문의 상태 메시지

이런 정보는 우측 상단 HUD 또는 별도 popover로 분리합니다.

## 8. 다른 플레이어의 공개 보유 카드 보기

각 플레이어가 획득한 숫자 카드는 공개 정보지만 모든 카드를 좌석 주변에 항상 펼쳐두면 7인 게임에서 화면이 지나치게 복잡해집니다.

따라서 좌석 본체 옆에 작은 카드 보기 조작 요소를 둡니다.

형태:

- 작은 버튼
- 작은 카드 모양 버튼
- 좌석에 자연스럽게 붙은 보조 컨트롤

중요한 점은 이 요소가 플레이어 좌석의 정보 덩어리를 크게 만들지 않는 것입니다.

데스크톱:

- hover 시 해당 좌석 근처에 popover 표시
- click으로도 열 수 있도록 설계 가능

모바일 / 터치:

- hover가 없으므로 tap/click이 기본 동작

popover 내용:

- 해당 플레이어가 획득한 공개 숫자 카드
- 오름차순 정렬
- 화면 전체를 가리는 모달이 아니라 좌석 근처의 작은 floating panel
- 카드가 많아도 popover가 과도하게 커지지 않도록 겹침 또는 compact layout 적용 가능

## 9. 우측 상단 플레이어 현황 HUD

기존의 큰 우측 플레이어 현황 영역은 제거합니다.

대신 게임 보드판 내부 우측 상단에 작은 HUD를 둡니다.

HUD에서 관리할 정보:

- 방 코드
- 현재 인원 / 최대 인원
- 플레이어 목록
- ready 상태
- 연결 상태 / 재접속 대기
- 방장 여부
- 필요한 최소한의 room 상태

디자인 원칙:

- 보드판보다 눈에 띄면 안 됨
- 작은 floating card 형태
- 필요 시 접기/펼치기 가능
- 7인에서도 과도하게 높아지지 않도록 compact row 사용
- 게임 중앙 오브젝트와 좌석을 가리지 않음

## 10. WAITING 상태도 동일한 보드판 사용

게임 시작 전 로비에서도 완전히 다른 대기 화면을 사용하지 않습니다.

Can’t Stop처럼 게임 보드판을 먼저 보여주는 구조로 바꿉니다.

대기실 상태:

- 테이블 중앙은 아직 게임 시작 전 상태
- 자신의 좌석은 항상 6시에 표시
- 다른 플레이어가 참가하면 HUD에는 즉시 참가 상태가 보일 수 있음
- 준비 완료된 플레이어는 테이블 주변 실제 좌석에 앉은 상태로 표현

### 준비 완료 착석 애니메이션

일반 플레이어가 준비 완료를 누르면:

1. 해당 플레이어가 ready 상태가 됨
2. 해당 플레이어의 좌석 위치가 확정됨
3. 플레이어 UI가 테이블 주변 좌석으로 들어오는 짧은 착석 애니메이션 실행
4. 빈 좌석이 하나씩 채워지는 느낌을 줌

현재 구조상 방장은 별도 ready 버튼 없이 준비된 것으로 취급하므로 방장 본인 좌석은 방 생성 후 기본적으로 테이블에 배치된 상태를 유지합니다.

애니메이션 원칙:

- 너무 길지 않게
- 반복 게임에서 피로하지 않게
- 레이아웃 재계산 중 순간이동처럼 보이지 않게
- prefers-reduced-motion 사용 시 최소화

## 11. 개인 패널 위치

게임 보드판 바로 아래에 보드판과 거의 같은 가로폭의 개인 패널을 둡니다.

개인 패널은 현재 사용자의:

- 정확한 칩 상태
- 본인 보유 카드
- 현재 가능한 액션

을 한 곳에 모은 개인 콘솔입니다.

## 12. 개인 패널 높이 정책

개인 패널은 충분한 정보량을 담아야 하지만 지나치게 높아지면 안 됩니다.

문제:

플레이어가 많은 카드를 가져갈 경우 카드 전체를 펼쳐두면 패널 높이가 계속 커질 수 있습니다.

그 결과:

- 보드판과 패널을 동시에 보기 어려움
- 매 턴마다 위아래 스크롤 필요
- 실제 플레이 흐름이 끊김

해결 방향:

개인 패널 높이는 비교적 일정하게 유지하고 카드를 수평으로 겹쳐서 배치합니다.

즉 포커 플레이어가 손패를 펼쳐 들고 있는 것과 비슷한 방식입니다.

## 13. 내 보유 카드 겹침 레이아웃

내가 획득한 카드가 많아질수록 수평 방향으로 일정 비율씩 겹칩니다.

카드 개수가 적을 때:

- 겹침을 적게
- 카드 디자인 전체를 비교적 많이 보여줌

카드 개수가 많을 때:

- 겹침 간격을 줄여 패널 폭 안에 최대한 수용
- 카드 숫자의 왼쪽 상단은 항상 보이도록 유지

최종 목표:

- 패널 높이가 크게 늘어나지 않음
- 수직 스크롤이 필요 없음
- 카드 목록이 정돈되어 보임
- 숫자를 빠르게 확인할 수 있음

## 14. 카드 디자인

카드는 실제 No Thanks! 보드게임 카드의 색감과 분위기를 참고합니다.

색상:

- blue 계열
- teal / green 계열
- yellow 계열
- pink / red 계열

등 원본 카드가 주는 value-based color family를 참고합니다.

숫자 위치:

- 왼쪽 상단
- 오른쪽 하단

실물 카드처럼 위아래 반전 숫자는 넣지 않습니다.

이 구조를 선택하는 핵심 이유는 개인 패널에서 카드가 포커 손패처럼 겹쳐 있어도 왼쪽 상단 숫자를 계속 볼 수 있기 때문입니다.

## 15. 내 카드 hover 인터랙션

개인 패널에서 겹쳐진 카드 중 하나에 마우스를 올리면 해당 카드를 강조합니다.

hover된 카드는:

- 위쪽으로 살짝 올라옴
- 다른 카드보다 조금 크게 확대
- z-index를 올려 전체 디자인이 잘 보임
- 부드러운 transition 사용

목적:

- 카드가 많이 겹쳐 있어도 개별 카드를 확인하기 쉬움
- 포커 게임처럼 손패를 살펴보는 재미 제공
- 단순 데이터 목록보다 게임 몰입감 강화

터치 환경에서는 hover 대신 tap/selection에 대응할 수 있도록 구조를 잡습니다.

## 16. 내 칩 표시

개인 패널에는 본인의 정확한 보유 칩 수를 표시합니다.

두 가지 표현을 함께 사용합니다.

1. 시각적 칩 더미
2. 정확한 숫자

칩 더미 디자인:

- 반드시 일렬일 필요 없음
- 적당히 겹쳐도 됨
- 작은 클러스터로 정돈
- 실제 칩이 잘 정리되어 있는 느낌
- 칩이 많아져도 화면을 지저분하게 만들지 않음

정확한 개수는 숫자로 제공하므로 실제 칩 오브젝트 개수와 1:1로 모두 그릴 필요는 없습니다.

## 17. 개인 패널 액션

핵심 액션은 개인 패널 안에 배치합니다.

주요 버튼:

- 거절하기 · 칩 1개 내기
- 카드 가져오기 · +N칩

내 차례가 아니면:

- 버튼 비활성
- 현재 누구 차례인지 간단 안내

내 칩이 0개라면:

- 거절 버튼 비활성 또는 숨김
- 카드 가져오기가 유일한 행동임을 명확히 표시

방장 게임 종료 같은 관리 액션은 핵심 플레이 버튼과 동일한 시각적 우선순위를 갖지 않게 보조 영역으로 분리합니다.

## 18. 테이블 애니메이션 이벤트

원형 테이블 위의 작은 카드와 칩은 실제 상태를 모두 표현하기 위한 것이 아니라 게임 이벤트를 시각화하는 오브젝트 역할도 합니다.

### 거절하기

현재 플레이어가 거절하면:

- 해당 플레이어 방향에서
- 작은 칩 하나가
- 중앙 카드 방향으로 이동

### 카드 가져오기

현재 플레이어가 카드를 가져가면:

- 현재 카드가 해당 플레이어 좌석 방향으로 이동
- 중앙 칩들도 함께 해당 플레이어 방향으로 이동
- 이후 다음 카드가 deck에서 중앙으로 등장

원칙:

- 애니메이션 자체가 상태를 결정하지 않음
- 서버 결과를 받은 뒤 시각적으로 표현
- reconnect 시 애니메이션 replay보다 최신 snapshot 복원을 우선

## 19. 영역별 정보 책임

### 플레이어 좌석

- 닉네임
- 현재 차례

### 좌석 근처 카드 보기 컨트롤

- 해당 플레이어의 공개 보유 카드 popover 열기

### 우측 상단 HUD

- 플레이어 목록
- ready
- 연결 / 재접속 대기
- 방장
- 방 코드 / 인원 정보

### 개인 패널

- 내 정확한 칩 수
- 내 보유 카드 전체
- 내 핵심 행동

### 중앙 테이블

- 현재 공개 카드
- 중앙 칩
- draw deck
- 게임 이벤트 애니메이션

## 20. WAITING → PLAYING 전환

게임 시작 버튼을 누른다고 화면 전체가 다른 DOM 구조로 교체되는 느낌을 최소화합니다.

WAITING에서도 이미:

- 게임 보드판
- 원형 테이블
- 좌석
- HUD

가 존재합니다.

PLAYING 전환 시:

- 테이블 중앙에 카드 더미 등장
- 첫 카드 공개
- 중앙 게임 오브젝트 활성화
- 개인 패널이 gameplay action 상태로 전환
- 첫 active player 좌석 강조

즉 같은 게임 공간이 자연스럽게 시작되는 느낌을 목표로 합니다.

## 21. 3~7인 좌석 UX

3인:

- 빈 공간이 너무 커 보이지 않게 테이블과 좌석 거리 보정

4~5인:

- 기본 원형 레이아웃의 기준

6~7인:

- 좌석 UI 크기를 과도하게 줄이기보다 테이블 주변 반지름/보드판 활용 공간을 넓게 사용
- HUD와 좌석이 겹치지 않도록 우측 상단 safe area 확보

7인까지 들어와도 화면이 관리자 대시보드처럼 보이지 않고 실제 테이블 주위에 사람이 둘러앉은 느낌을 유지해야 합니다.

## 22. 반응형 방향

### 데스크톱

- 원형 좌석
- hover popover
- 카드 hover raise
- HUD

를 먼저 완성합니다.

동일한 기능 의미를 유지하되 레이아웃은 후속 조정 가능합니다.

필수 원칙:

- 본인 좌석 6시 기준 유지

## 23. 기존 서버 구조에서 변경하지 않을 것

- 9장 제외 / 24장 사용
- 시작 칩 규칙
- 점수 계산

- room version
- client_action_id
- public/private state 경계
- Realtime invalidation 방식
- Presence authorization 경계

UI 변경 때문에 서버 권위나 private-state 경계를 약하게 만들지 않습니다.

## 27. 구현 시 주의사항

- 기존 Game Platform 공통 구조를 불필요하게 수정하지 않습니다.
- No Thanks! game-local UI 안에서 해결 가능한 것은 game-local로 유지합니다.
- 다른 게임에 영향을 주는 shared refactor는 이번 단계에서 하지 않습니다.
- 공개 카드 popover에서 private counter 또는 private deck 정보가 섞이지 않게 합니다.
- 좌석 회전은 UI 표현만 바꾸며 서버 seat/turn order를 수정하지 않습니다.
- ready 착석 애니메이션과 gameplay 애니메이션은 authoritative snapshot과 분리합니다.
- reconnect 시 애니메이션보다 최신 서버 상태 복원을 우선합니다.
- 7인에서도 HUD / 좌석 / 중앙 테이블이 겹치지 않는지 반드시 검증합니다.
- 개인 패널 카드 수가 많아져도 패널 높이가 무한히 커지지 않게 합니다.
