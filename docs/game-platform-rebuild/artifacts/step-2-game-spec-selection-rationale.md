## 기록 예시 — 지원 구현 선언이 아님

> 이 모드는 카드 규칙을 사용하지만 참가자가 동시에 접속할 필요는 없다. 장르 규칙은 보드·카드를 적용하고 진행은 순차 턴, 지속성은 장기 저장·재개 요구로 기록한다. 이 선택만으로 특정 Runtime Model이나 DB/RPC 구현을 확정하지 않는다. 현재 계약의 충족 여부는 별도 검토한다.

| 예시 상세 항목 | 값 |
|---|---|
| 적용 조건 | 해당 카드 모드. 다른 mode의 선택을 대신하지 않음 |
| flow·시간 | 순차 턴·이벤트 기반; 마감 여부 미결정 |
| 세션·지속성 | 장기 진행 및 저장/재개 요구 |
| 참여·가시성 | 동시 접속 필수 아님; 역할/비공개 정보는 게임 규칙 조사 후 결정 |
| 권위·동기화·복원 | 현재 계약 적합성 미확인; 새 계약/구현 미채택 |
| 공간·렌더링·입력·물리 | 미결정; 카드 장르만으로 DOM/Canvas/물리를 결정하지 않음 |
| 결과·meta | 미결정; match 결과와 장기 progression 따로 기록 |
| Capability | Invite/Presence 미결정; 불필요한 default 사용 처리 없음 |
| 규칙·검증 | 원 규칙 조항·출처 확인, rematch 조건과 후속 설계 검토 필요 |

이 예시는 STEP 3 전수 stress matrix나 특정 게임의 GAME_SPEC 확정이 아니다. 필요한 특성은 STEP 2에서 표현하고 소유 API/모델 계약은 STEP 4/5/6으로 연결한다.

## 미결정 보존

Astra 제안을 승인된 계약/구현으로 바꾸지 않는다. 새로운 장르 상세 문서·최종 모델·물리 배치·Core 책임·권위/동기화/복원 계약·Capability API·성능 값·구체 타이밍 판정은 후속 검토 대상이다. 초기 시작만 hostless이고 재대결은 기존 의무를 충족하는 경우에는 초기 hostless만으로 규칙 변경 대상으로 단정하지 않는다. 멀티플레이 재대결에서도 게임 규칙상 host가 성립하지 않으면 별도 플랫폼 규칙 변경 검토 대상이며, 재대결 정책이 미정이면 현재 규칙 적합성 미확인으로 기록한다. hostless라는 표현만으로 rematch 준수·계약 호환·구현 지원을 선언하지 않는다. GAME_SPEC 항목의 실제 책임 절/템플릿 갱신도 STEP 6/7에서 확인한다.
