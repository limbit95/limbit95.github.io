## 3. 의미 대응 검토와 한계

기존 원문/source bytes와 승인 f 목적지를 비교하고 해당 실제 owner anchor 도달을 확인했다. 기존 같은 scope의 의무를 삭제·강도 완화·다른 owner로 자동 재분류하지 않았다. nested/server 발견과 같은 적용 단위의 문서/검사 연결을 보완했다. 기존 online DB 요구를 검사 준비 없이 삭제하지 않았고 local 수명/최종 채택도 N/A로 없애지 않았다. source blob·원문 정규화 hash와 실제 검사/안내 역할을 구별한다.

새 의미 충돌을 발견하지 않아 별도 Astra 재판단/사후 감사 없이 T1→T3→T4로 진행했다. 정확한미지원 nonDB 모델/취소·시간공백/oracle·실제server 공개 제외는 원 후속 gate에 남긴다. 관련ID/f의 수·자동 대응만으로 전수 의미 검토 완료를 주장하지 않는다.
