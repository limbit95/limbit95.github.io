# Marble Auction v2 — Requirements Definition

업데이트 기준: 2026-09-18

이 문서는 실제 Classic 플레이테스트를 바탕으로 Phase 7A Auction의 **UI, 진행 lifecycle, 시작가 규칙을 재정의하기 위한 제품 요구사항**입니다.

현재 Phase 7A v1의 서버 권위 / Realtime / idempotency 기반은 이미 구현 완료되어 있습니다. Auction v2는 그 기반을 가능한 한 유지하면서 플레이 흐름을 다음 방향으로 바꿉니다.

> 도시 구매 포기 → 10초 경매 요청 → 10초 참가자 모집 → 1명이면 자동 매입 / 2명 이상이면 경쟁 경매

이 문서는 구현 지시서가 아니라 요구사항 기준 문서입니다. 아직 미확정으로 표시된 항목은 구현 전에 별도로 결정합니다.

## 1. 문제 정의

현재 경매는 구매 거절 이후 요청과 실제 입찰의 경계가 충분히 분리되어 있지 않고, 구매를 포기한 플레이어에게도 경매 요청 UI가 노출되어 플레이 흐름의 주도권이 불명확하게 느껴집니다.

또한 도시 정가와 경매 시작가의 차이가 없으면 해당 타일에 직접 도착하지 않은 플레이어가 도시를 지나치게 쉽게 확보할 수 있어 일반 구매의 가치가 약해질 수 있습니다.

Auction v2는 다음 문제를 해결하는 것을 목표로 합니다.

- 구매를 포기한 플레이어의 역할을 명확히 종료
- 경매 개최 의사와 실제 경매 참가 의사를 분리
- 경매 요청에 경제적 책임 부여
- 일반 구매보다 경매 구매에 명확한 가격 프리미엄 부여
- 경쟁자가 없는 경매를 불필요하게 길게 진행하지 않음
- 실제 경매는 2명 이상이 참여할 때만 진행

## 2. 용어

### 구매 우선권자

해당 도시 타일에 직접 도착하여 최초 구매 기회를 받은 플레이어입니다.

### 구매 포기자

구매 우선권자가 도시 구매를 거절한 이후의 상태를 의미합니다.

구매 포기자는 해당 도시의 Auction v2에서 다음 권한을 갖지 않습니다.

- 경매 요청
- 참가 신청
- 입찰

### 최초 경매 요청자

1차 10초 경매 요청 단계에서 가장 먼저 유효한 경매 요청을 서버에 확정한 플레이어입니다.

최초 요청자는 단순한 투표자가 아니라 **경매 시작가에 해당 도시를 구매할 의무를 가진 플레이어**입니다.

### 경매 참가자

최초 요청자와 2차 참가 모집 단계에서 경매 참가를 선택한 플레이어를 의미합니다.

## 3. 확정된 전체 lifecycle

### Step 0. 도시 구매 포기

구매 우선권자가 도시 구매를 포기하면 일반 구매 절차를 종료하고 해당 도시를 Auction v2 후보 상태로 전환합니다.

요구사항:

- 구매 포기자에게 경매 요청용 하단 카드 / 액션 버튼을 노출하지 않습니다.
- 구매 포기자는 이후 요청 / 모집 / 입찰의 주도권을 갖지 않습니다.
- 도시는 아직 미소유 상태를 유지합니다.

### Step 1. 경매 요청 — 10초

도시 구매 포기 직후 화면 중앙에 경매 개최 여부를 묻는 요청 UI를 표시합니다.

목적:

- 실제 입찰을 시작하는 단계가 아닙니다.
- 다른 플레이어 중 최소 한 명이 해당 도시를 시작 경매가에 구매할 의사가 있는지 확인하는 단계입니다.

동작:

- 10초 countdown을 시작합니다.
- 구매 포기자를 제외한 경매 가능 플레이어가 경매 요청을 할 수 있습니다.
- 10초 동안 아무도 요청하지 않으면 경매는 열리지 않습니다.
- 해당 도시는 미소유 상태로 남고 기존 턴 종료 흐름으로 복귀합니다.
- 최초 유효 요청이 발생하면 1차 요청 단계는 종료하고 즉시 참가자 모집 단계로 전환합니다.

### Step 2. 경매 참가자 모집 — 10초

최초 요청자가 발생하면 즉시 실제 경매를 시작하지 않습니다.

화면 중앙에 다음 의미의 별도 모집 모달을 표시합니다.

> 경매가 곧 시작됩니다. 참여하시겠습니까?

동작:

- 모집 시간은 10초입니다.
- 최초 요청자는 자동으로 참가자에 포함됩니다.
- 최초 요청자는 참가 모집 단계에서 참가를 취소할 수 없습니다.
- 구매 포기자는 참가 대상에서 제외됩니다.
- 시작 경매가를 지불할 수 있는 골드를 보유한 플레이어만 참가할 수 있습니다.
- 시작 경매가보다 보유 골드가 부족한 플레이어에게는 참가 액션을 허용하지 않습니다.
- 다른 eligible 플레이어는 참가 여부를 선택할 수 있습니다.
- 응답하지 않은 플레이어는 모집 종료 시 비참가로 처리합니다.
- 10초가 끝나면 최종 참가자 수를 서버 상태 기준으로 확정합니다.

### Step 3-A. 참가자 1명 — 자동 매입

최종 참가자가 최초 요청자 1명뿐이라면 경쟁 입찰 화면을 열지 않습니다.

최초 요청자가 시작 경매가로 해당 도시를 자동 매입합니다.

필수 결과:

- 시작 경매가만큼 골드 자동 차감
- 도시 소유권을 최초 요청자에게 이전
- 화면 중앙에 매입 성공 결과 표시
- 기존 일반 도시 구매와 동일 계열의 구매 animation 재사용
- 기존 도시 구매와 동일 계열의 coin / money movement presentation 재사용
- 완료 후 기존 턴 흐름으로 복귀

권장 결과 문구의 의미:

> 매입에 성공하셨습니다

정확한 문구와 디자인은 UI 구현 단계에서 조정할 수 있습니다.

### Step 3-B. 참가자 2명 이상 — 경쟁 경매

최종 참가자가 2명 이상이면 실제 경쟁 경매를 시작합니다.

경매 시작 시:

- 최초 요청자를 시작 경매가의 최고 입찰자로 자동 등록합니다.
- 최초 요청자는 별도 클릭 없이 시작 경매가를 자동 입찰한 상태가 됩니다.
- 이후 다른 참가자에게 입찰 기회를 넘깁니다.
- 각 플레이어의 수동 입찰 차례 제한시간은 10초입니다.
- 자신의 입찰 차례에는 `입찰` 또는 `포기` 액션을 선택합니다.
- 최초 요청자도 시작가 자동 입찰 이후 다른 플레이어에게 최고가를 빼앗기고 자신의 차례가 다시 오면 `입찰` 또는 `포기`를 선택할 수 있습니다.
- 이미 포기한 플레이어는 해당 경매에 다시 참여할 수 없습니다.
- 경쟁 중 가격이 상승해 어떤 참가자가 더 이상 유효한 다음 입찰가를 지불할 수 없게 되면 해당 참가자는 자동으로 경매 참여에서 제외됩니다.

최초 요청자에게 자동 입찰 책임을 부여하는 이유:

- 무책임한 경매 요청 방지
- 경매 요청 자체에 실제 구매 의사 부여
- 일반 구매 거절 후 모든 도시가 습관적으로 경매에 올라오는 상황 방지

## 4. 시작 경매가

Auction v2 초기 규칙:

> 시작 경매가 = 도시 기본 구매가 + 기본 구매가의 50%

즉:

> 시작 경매가 = 기본 구매가 × 150%

예시:

- 도시 기본가 200골드 → 시작 경매가 300골드
- 도시 기본가 400골드 → 시작 경매가 600골드

목적:

- 직접 해당 타일에 도착해 얻는 일반 구매 우선권의 가치를 보호
- 다른 플레이어가 경매만을 통해 도시를 지나치게 쉽게 확보하는 현상 방지
- 경매 요청을 전략적 선택으로 만듦

150%는 Auction v2의 **초기 밸런스 값**입니다.

실제 플레이테스트 결과에 따라 이후 조정할 수 있지만, 별도 결정 전까지 초기 기준은 150%로 둡니다.

## 5. 요청자의 구매 의무

경매 요청 버튼의 의미는 다음과 같이 정의합니다.

> 이 경매가 열린다면 나는 최소 시작 경매가에 이 도시를 구매하겠습니다.

따라서 최초 요청자는 다음 책임을 가집니다.

- 참가 모집에서 자동 참가
- 참가 취소 불가
- 단독 참가 시 시작가 자동 매입
- 2명 이상 참가 시 시작가 자동 첫 입찰

UI는 사용자가 이 책임을 모른 채 실수로 경매를 요청하지 않도록 시작 경매가와 요청 결과를 명확히 알려야 합니다.

## 6. UI 요구사항

### 구매 포기자

- 경매 요청 액션 카드 미노출
- 경매 요청 / 참가 / 입찰 버튼 미노출
- 필요할 경우 현재 경매 진행 상태만 read-only로 보여줄 수 있음

### 1차 요청 모달

반드시 이해 가능해야 하는 정보:

- 대상 도시
- 도시 기본 구매가
- 시작 경매가
- 10초 countdown
- 경매 요청 시 발생하는 구매 의무
- 경매 요청 버튼

핵심 메시지:

- 요청은 단순 투표가 아님
- 요청자가 시작 경매가에 대한 구매 책임을 가짐

### 2차 참가 모집 모달

반드시 이해 가능해야 하는 정보:

- 대상 도시
- 최초 요청자
- 시작 경매가
- 남은 모집 시간
- 현재 참가 예정 인원
- 참가 버튼
- 비참가 선택 또는 아무 행동 없이 timeout 가능

### 단독 매입 결과

- 매입 성공 표시
- 실제 차감 금액
- 소유권 획득 확인
- 구매 animation
- coin movement

### 경쟁 경매 화면

경매 시작 시 반드시 보여줄 정보:

- 대상 도시
- 도시 기본가
- 경매 시작가
- 현재 최고 입찰가
- 다음 최소 유효 입찰가
- 최초 요청자가 시작가로 자동 입찰했다는 사실
- 현재 최고 입찰자
- 참가자 상태
- 자신의 보유 골드
- 자신의 입찰 차례 남은 시간 10초
- `입찰` / `포기` 액션

보유 골드가 다음 최소 유효 입찰가보다 부족해 더 이상 입찰할 수 없는 참가자는 자동으로 참여 종료 상태가 표시되어야 합니다.

## 7. 기존 Phase 7A에서 변경되는 규칙

### v1

- 도시 구매 거절
- AUCTION_REQUEST
- 요청자 1명 이상이면 PROPERTY_AUCTION
- 시작가는 도시 정가
- 요청자는 첫 유효 입찰 전 자발적 패스 불가

### v2

- 도시 구매 거절
- 10초 경매 요청
- 최초 요청자 확정
- 10초 참가자 모집
- 참가자 1명 → 시작가 자동 매입
- 참가자 2명 이상 → 요청자 시작가 자동 입찰 후 경쟁 경매
- 시작가는 도시 정가의 150%

따라서 Auction v2는 단순 UI 변경이 아니라 다음 세 범주를 모두 포함합니다.

- UI 수정
- 플레이 흐름 수정
- 게임 규칙 수정

## 8. 유지하는 기존 Phase 7A 원칙

이번 요구사항에서 변경을 명시하지 않은 다음 기반은 유지하는 것을 기본 원칙으로 합니다.

- 구매 포기자는 해당 경매 입찰 제외
- 파산 플레이어 제외
- 보유 골드 초과 입찰 금지
- 패스한 플레이어 재참여 금지
- 현재 최고 입찰자는 패스 불가
- 최종 낙찰 시 서버 authoritative 골드 차감 + 소유권 이전
- expected_version optimistic concurrency
- client_action_id replay / idempotency
- Realtime 이후 authoritative snapshot refresh
- stale snapshot / stale response 방어
- reconnect 시 서버 상태로 수렴
- 경매 진행 중 legacy endTurn 우회 차단

이 항목도 실제 구현 영향 분석에서 충돌이 발견되면 별도 요구사항으로 다시 검토합니다.

## 9. 타이머 요구사항

제품 규칙으로 확정된 시간:

- 경매 요청: 10초
- 참가자 모집: 10초
- 경쟁 경매의 각 수동 입찰 차례: 10초

온라인 구현 시 countdown의 최종 기준은 클라이언트 로컬 타이머가 아니라 서버가 가진 authoritative deadline이어야 합니다.

재접속 / 새로고침 시:

- 현재 단계
- 서버 deadline
- 남은 시간
- 이미 확정된 요청자 / 참가 상태

를 snapshot에서 복원할 수 있어야 합니다.

timeout 결과는 서버가 확정합니다.

## 10. Presentation 요구사항

단독 자동 매입과 경쟁 경매 낙찰은 기존 도시 구매 presentation과 의미적으로 연결되어야 합니다.

필수 후보:

- 골드 차감 count-down
- coin / money 이동
- 도시 ownership color 전환
- 도시 구매 / 획득 animation
- 낙찰 / 매입 결과 강조

Animation은 게임 결과를 결정하지 않으며 서버가 먼저 확정한 결과를 재생합니다.

## 11. 추가 확정된 자금 / 포기 규칙

### 11.1 요청 가능 자금 기준

최초 경매 요청자는 요청 시점에 시작 경매가를 지불할 수 있는 골드를 보유해야 합니다.

시작 경매가보다 보유 골드가 부족하면 경매 요청을 할 수 없습니다.

### 11.2 참가 신청 자금 기준

다른 플레이어 역시 참가 모집 시점에 시작 경매가를 지불할 수 있는 골드를 보유해야 합니다.

시작 경매가보다 보유 골드가 부족하면 경매 참가를 신청할 수 없습니다.

### 11.3 경쟁 중 자금 부족 자동 제외

경쟁 경매가 진행되면서 입찰가가 상승할 수 있습니다.

참가자의 실제 입찰 가능 여부는 단순한 현재 최고가가 아니라 **다음 최소 유효 입찰가를 지불할 수 있는지**를 기준으로 판정합니다.

- 다음 최소 유효 입찰가 <= 보유 골드: 참가 유지
- 다음 최소 유효 입찰가 > 보유 골드: 자동 참여 종료
- 자동 참여 종료된 플레이어는 해당 경매에 다시 참여할 수 없음
- 서버 authoritative state에서 이 상태를 확정

이 기준은 현재 Phase 7A의 최소 입찰가 규칙인 `max(시작가, 최고가 + 1)`을 전제로 합니다. 향후 bid increment 규칙이 변경되면 동일하게 "다음 최소 유효 입찰가를 지불할 수 있는가"를 기준으로 적용합니다.

### 11.4 수동 포기

경쟁 경매에서 자신의 입찰 차례가 왔을 때 플레이어는 다음 두 액션 중 하나를 선택합니다.

- 입찰
- 포기

포기한 플레이어는 해당 경매에서 즉시 제외되며 다시 참가할 수 없습니다.

최초 요청자는 시작 경매가 자동 입찰 자체를 취소할 수는 없지만, 이후 다른 참가자의 더 높은 입찰로 최고 입찰자 지위를 잃고 자신의 차례가 다시 오면 일반 참가자와 동일하게 포기할 수 있습니다.

### 11.5 입찰 제한시간

각 수동 입찰 차례의 제한시간은 10초로 확정합니다.

- 10초 안에 `입찰` 또는 `포기`를 선택해야 합니다.
- 10초 동안 아무 액션도 하지 않으면 서버에서 자동으로 `포기` 처리합니다.
- timeout 자동 포기는 수동 포기와 동일하게 해당 경매 재참여가 불가능합니다.
- timeout 결과는 서버 authoritative state에서 확정합니다.

## 12. 아직 미확정인 제품 규칙

다음 항목은 아직 결정하지 않았으므로 구현 전에 확정해야 합니다.

### 12.1 150% 계산의 정수 rounding

기본 구매가가 홀수 등으로 인해 1.5배가 정수가 아닐 경우:

- floor
- ceil
- round
- 가격 단위 자체를 조정

중 어떤 정책을 사용할지 확정해야 합니다.

### 12.2 경쟁 경매의 입찰 순서

최초 요청자의 자동 입찰 이후 누구에게 첫 수동 입찰 차례가 가는지 결정해야 합니다.

후보:

- 현재 턴 순서 기준
- 최초 요청자 다음 좌석부터
- 참가 신청 순서
- 별도 경매 순서

### 12.3 참가 모집 중 신청 철회

경쟁 경매 시작 후 자신의 차례에서 포기하는 규칙은 확정되었습니다.

다만 2차 참가 모집 10초 안에 참가 버튼을 누른 일반 참가자가 **모집 종료 전 참가 신청 자체를 다시 취소할 수 있는지**는 아직 미확정입니다.

### 12.4 동시 경매 요청

네트워크상 여러 플레이어가 거의 동시에 요청했을 때 어떤 UX를 보여줄지 확정해야 합니다.

서버에서는 단일 최초 요청자만 확정해야 하며, 후발 요청을 참가 신청으로 자동 전환할지 여부는 별도 결정합니다.

### 12.5 disconnect 처리

- 최초 요청자가 요청 후 이탈
- 참가자가 모집 후 이탈
- 경쟁 입찰 중 이탈

각 경우의 timeout / 자동 패스 / 구매 의무 유지 여부를 별도로 확정합니다.

## 13. 구현 전 acceptance 기준

Auction v2 구현을 시작하기 전에 최소 다음 제품 조건이 문서상 확정되어 있어야 합니다.

1. 구매 포기자는 경매 요청 UI를 받지 않는다.
2. 구매 포기자는 경매 참가 / 입찰에서 제외된다.
3. 요청 단계는 10초다.
4. 아무 요청도 없으면 경매 없이 종료한다.
5. 첫 요청 발생 시 참가 모집 단계로 전환한다.
6. 참가 모집 단계는 10초다.
7. 최초 요청자는 자동 참가하며 철회할 수 없다.
8. 참가자 1명이면 시작가에 자동 매입한다.
9. 단독 매입에서도 기존 도시 구매 animation / coin movement를 재사용한다.
10. 참가자 2명 이상이면 경쟁 경매를 연다.
11. 최초 요청자는 시작가를 자동 첫 입찰한다.
12. 초기 시작가는 도시 기본가의 150%다.
13. server authoritative state / Realtime / idempotency 기반을 유지한다.
14. 경매 요청자와 참가자는 시작 경매가를 지불할 골드가 있어야 한다.
15. 경쟁 중 다음 최소 유효 입찰가가 보유 골드를 넘으면 자동 참여 종료한다.
16. 각 수동 입찰 차례는 10초다.
17. 자신의 입찰 차례에는 입찰 또는 포기를 선택할 수 있다.
18. 입찰 차례에서 10초 동안 무응답이면 자동 포기 처리한다.
19. 미확정 예외 규칙을 구현 전에 결정한다.

## 14. 구현 범위에 아직 포함하지 않는 것

요구사항 확정 전에는 다음을 바로 구현하지 않습니다.

- 새로운 bid increment 정책
- 경매 취소 기능
- AI / bot 참가
- 시작가 150% 이외의 동적 경매가 공식
- 기존 Trade / Liquidation 규칙 변경
