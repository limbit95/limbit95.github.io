# Marble Classic — Feature & Presentation Candidate Backlog

업데이트 기준: 2026-09-18

이 문서는 Marble Worlds의 **Classic 모드를 더 재미있고 완성도 높게 만들기 위한 후보 목록**을 보존하는 검토 문서입니다.

이 문서에 기록된 항목은 구현 확정 사항이 아닙니다.

- 후보를 잊지 않기 위해 기록합니다.
- 실제 Phase 편입 여부와 우선순위는 착수 전에 별도로 결정합니다.
- 후보가 기록되어 있다는 이유만으로 규칙이나 UI를 선제 구현하지 않습니다.
- Classic의 단순한 보드게임 흐름을 해치지 않는지 플레이테스트를 통해 판단합니다.
- 기능 재미와 시각적 재미를 별개의 축으로 보되, 실제 개발 시 필요한 기본 presentation은 함께 검토합니다.

## 1. Gameplay 후보

### 1.1 Luck Resource / 운 조절

목표:
- 완전한 주사위 운만으로 게임이 흘러가는 느낌을 줄입니다.
- 제한된 자원을 언제 소비할지 판단하는 전략 요소를 만듭니다.

후보 예시:
- 주사위 재굴림
- 결과 범위 보정
- 특정 조건에서 이동값 보정
- 운 조절 자원 충전 / 소비

주의:
- 원하는 숫자를 자유롭게 고르는 수준까지 허용할지는 별도 밸런스 검토가 필요합니다.
- 서버가 최종 결과를 결정하는 원칙은 유지합니다.

### 1.2 Secret Mission / 개인 비밀 목표

목표:
- 단순 자산 경쟁 외에 플레이어마다 다른 전략적 목적을 제공합니다.
- 상대가 무엇을 노리는지 추측하는 재미를 추가합니다.

후보 예시:
- 특정 지역 소유
- 일정 수 이상의 도시 보유
- 특정 건설 단계 달성
- 일정 자산 규모 달성
- 특정 행동 성공

검토 항목:
- 보상 방식
- 공개 시점
- 실패 / 교체 규칙
- 게임 승리 조건과의 관계

### 1.3 Reaction Cards / 반응 카드

목표:
- 자신의 턴이 아닐 때도 플레이어가 게임에 개입할 수 있게 합니다.

후보 예시:
- 통행료 감소 / 방어
- 이동 결과에 제한적으로 개입
- 이벤트 무효화 / 변경
- 상대 행동에 대한 즉시 대응

주의:
- interrupt window, 동시 응답, 시간 제한, 응답 우선순위 등 온라인 동시성 설계가 필요합니다.
- 다른 후보보다 구현 난도가 높을 수 있으므로 독립 Phase로 다루는 것을 우선 검토합니다.

### 1.4 Shared / Global Events / 공동 이벤트

목표:
- 보드 전체의 상황을 변화시켜 반복 플레이의 정형화를 줄입니다.

후보 예시:
- 전 플레이어 세금 / 보너스
- 특정 지역 통행료 일시 증가
- 특정 지역 건설 비용 변화
- 경기 호황 / 침체
- 모든 플레이어가 영향을 받는 선택형 사건

검토 항목:
- 지속 턴 수
- 중첩 가능 여부
- 현재 턴과 효과 종료 시점
- reconnect 시 authoritative snapshot 복원

### 1.5 지역 독점 효과 강화

목표:
- 같은 색상 또는 지역의 도시를 모으는 전략적 목적을 강화합니다.

후보 예시:
- 통행료 배율
- 건설비 할인
- 보너스 골드
- 지역 완성 전용 효과

주의:
- 기존 부동산 가치와 통행료 밸런스를 크게 흔들 수 있으므로 수치 설계가 필요합니다.

### 1.6 랜드마크 / 최종 건설 단계

목표:
- 최대 건설에 경제적 보상과 시각적 성취를 동시에 부여합니다.

후보:
- 최종 건설 단계 전용 랜드마크
- 도시별 고유 외형
- 추가 통행료 또는 지역 효과
- Highlight 등급 건설 연출

이 후보는 Gameplay와 Final Visual 모두에 걸쳐 있습니다.

### 1.7 EVENT 다양화

목표:
- 단순 골드 증감 위주의 EVENT를 다양한 상황 변화로 확장합니다.

후보 예시:
- 특정 위치 이동
- 도시 / 지역 가격 변화
- 통행료 변화
- 플레이어 간 골드 이동
- 대상 플레이어 선택
- 일정 턴 동안 지속되는 효과

### 1.8 선택형 EVENT

목표:
- 랜덤 결과를 그대로 받는 대신 위험과 보상 사이에서 판단하게 합니다.

후보 예시:
- 비용을 내고 특정 이득 선택
- 안전한 보상 / 위험한 큰 보상 중 선택
- 이동 / 골드 / 자산 관련 선택지

### 1.9 역전 가능성 보완

목표:
- 중후반에 승패가 지나치게 빨리 고정되는 현상을 완화합니다.

방향:
- 단순 꼴찌 자동 보상보다 위험을 감수하면 높은 보상을 얻는 선택 구조를 우선 검토합니다.
- 선두 플레이어를 인위적으로 처벌하는 규칙은 신중하게 검토합니다.

### 1.10 플레이어 간 직접 상호작용 확대

현재 구현:
- Auction
- Trading / Negotiation
- Debt Recovery

추가 후보:
- 특정 EVENT에서 상대 지정
- 조건부 공동 선택
- 제한적 공동 투자
- 플레이어 간 일시적 협상 요소

### 1.11 특수 타일 확장

후보 예시:
- 순간이동
- 카드 획득
- 무료 / 할인 건설
- 위험 / 보상 선택
- 일시적 보드 효과

주의:
- Classic 보드의 즉시 이해 가능한 구조를 해치지 않는 범위에서 검토합니다.

### 1.12 Dice 재미 강화

후보 예시:
- 더블 결과 보너스
- 연속 더블 관련 규칙
- 특수 결과
- 주사위 결과에 연결되는 presentation 강화

게임 판정은 계속 서버 결과를 기준으로 합니다.

### 1.13 승리 조건 다양화

기본 Classic 승리 조건은 유지하면서 선택 가능한 룸 규칙 후보로 검토합니다.

후보:
- 최후 생존
- 제한 턴 후 총자산
- 목표 자산 달성
- 짧은 게임용 승리 조건

### 1.14 게임 템포 Preset

목표:
- 플레이 시간 선택권을 제공합니다.

후보:
- Quick Classic
- Standard Classic
- Long Classic

조절 가능 후보:
- 시작 골드
- START 보상
- 건설비
- 통행료 배율
- 최대 턴 수

정확한 수치는 플레이테스트 후 결정합니다.

### 1.15 관전성 / 비활성 턴의 재미

목표:
- 자신의 턴이 아닐 때도 게임을 지켜보는 재미를 높입니다.

대상:
- 큰 통행료
- 경매
- 거래
- 랜드마크 완성
- 자산 매각
- 파산
- 역전 상황

이 항목은 Gameplay보다는 Presentation과 강하게 연결됩니다.

## 2. Final Visual / Presentation 후보

현재 Classic의 고정 쿼터뷰 2.5D 방향은 유효하지만, **현재 절차적 도형과 기본 모델은 최종 그래픽이 아닙니다.**

최종 시각 완성 후보:

### 2.1 도시별 고유 랜드마크
- 현재 placeholder / procedural 표현을 실제 도시 정체성이 드러나는 모델로 교체
- 건설 단계와 자연스럽게 연결

### 2.2 캐릭터 모델
- 단순 말이 아니라 상황에 반응하는 플레이어 캐릭터
- idle
- 걷기
- 점프
- 착지
- 수금
- 손실
- 구매 / 건설 성공
- 파산
- 승리

### 2.3 건설 단계별 모델 변화
- 단계 상승 시 단순 수치 변화가 아니라 도시가 실제 성장하는 느낌 제공
- 최종 단계 랜드마크와 연결 가능

### 2.4 Money Presentation
- 플레이어 간 통행료 이동
- START 보상
- TAX 지출
- BONUS 수금
- 큰 금액에 대한 강화 연출

### 2.5 Dice Presentation
- 흔들림
- 투척
- 충돌
- 서버가 확정한 최종 눈 표시
- 더블 / 특수 결과 강조

### 2.6 EVENT Presentation
- 카드 등장
- 카드 뒤집기
- 내용 공개
- 대상 플레이어 / 타일 강조
- 실제 효과 연출

### 2.7 Camera Presentation
- 기본 고정 쿼터뷰 유지
- 중요한 순간에만 짧은 focus / zoom
- 랜드마크
- 큰 통행료
- 독점
- EVENT
- 파산
- 승리

### 2.8 VFX / Sound
- particle
- glow / impact
- UI motion
- sound effect
- 상황별 캐릭터 반응

### 2.9 품질 단계 / 접근성
- 모바일 성능 단계
- 저사양 fallback
- reduced motion
- animation skip / fast forward

## 3. 현재 별도 재검토가 필요한 기존 기능

### Auction UI / Flow

Phase 7A의 서버 권위 경매 규칙과 동기화 기반은 구현 완료 상태입니다.

다만 2026-09-18 실제 플레이테스트에서 **현재 경매 UI와 플레이 흐름은 사용성 측면에서 재검토가 필요**하다는 피드백이 확인되었습니다.

현재 이 문서에서는 구체적인 변경안을 임의로 확정하지 않습니다.

다음 작업에서 실제 플레이 중 불편했던 장면을 기준으로 다음을 분리해 요구사항을 정의합니다.

- 경매가 시작되는 계기와 안내 방식
- 경매 요청 단계가 필요한지 / 어떻게 보여줄지
- 참가자에게 현재 해야 할 행동이 명확한지
- 입찰가 입력 방식
- 최소 입찰가 / 보유 골드 / 현재 최고가 표시
- 입찰 / 패스 버튼 배치와 활성 조건
- 누가 입찰 중인지, 누가 패스했는지 표현
- 경매 종료 조건을 사용자가 이해할 수 있는지
- 낙찰 / 유찰 결과 presentation
- 모바일 화면에서의 조작 흐름
- 경매가 전체 게임 템포를 지나치게 끊는지

## 4. 후보를 Phase로 승격할 때의 원칙

후보를 실제 개발 Phase로 승격하기 전에 최소한 다음을 확정합니다.

1. 이 기능이 해결하려는 실제 플레이 문제
2. 플레이어가 얻는 재미
3. 핵심 규칙
4. 온라인 권위 상태
5. 다른 Advanced Gameplay와의 충돌
6. UI / UX 흐름
7. Presentation 요구사항
8. reconnect / stale snapshot / idempotency 영향
9. 회귀 테스트 범위
10. Classic의 복잡도를 과도하게 높이지 않는지

이 문서는 후보 저장소이며 실제 구현 순서는 [Marble Development Roadmap](./marble-development-roadmap.md)에서 별도로 확정합니다.
