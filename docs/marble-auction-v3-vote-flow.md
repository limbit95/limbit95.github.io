# Marble Auction v3 참가 투표 요구사항

> 이 문서는 Marble Classic 경매의 현재 canonical 제품 요구사항입니다.
> 기존 docs/marble-auction-v2-requirements.md의 ‘경매 요청 → 참가 모집’ 2단계 흐름을 대체합니다.

## 1. 목표

도시 구매 포기 이후 경매 진입 과정을 하나의 짧고 명확한 참가 투표로 단순화합니다.

핵심 흐름:

도시 구매 포기 → 15초 참가/포기 투표 → 0명 미소유 / 1명 자동 매입 / 2명 이상 경쟁 경매

## 2. 투표 대상

도시 구매 우선권을 가진 플레이어가 구매를 포기하면 즉시 경매 참가 투표를 엽니다.

투표 대상은 다음 조건을 모두 만족하는 플레이어입니다.

- 도시 구매 포기자가 아님
- 파산 상태가 아님
- 시작 경매가를 지불할 수 있음

시작 경매가는 도시 기본 구매가의 150%이며 소수점이 생기면 일반 반올림합니다.
시작가를 감당할 수 없는 플레이어는 투표 대상에서 제외하며 투표 종료를 지연시키지 않습니다.

## 3. 15초 참가 투표

투표 대상 플레이어가 취할 수 있는 행동은 경매 참가, 경매 포기, 아무 행동도 하지 않음의 세 가지입니다.
UI에서는 왼쪽에 ‘경매 참가’, 오른쪽에 ‘경매 포기’를 표시합니다.

### 3.1 선택은 한 번만 가능

참가/포기는 철회나 토글이 아닙니다.

- 참가 후 포기로 변경 불가
- 포기 후 참가로 변경 불가
- 같은 선택을 다시 제출할 수 없음
- 서버가 해당 플레이어의 첫 번째 유효 결정만 확정

따라서 기존 Auction v2의 ‘참가 철회’ 개념은 제거합니다.

### 3.2 미응답

15초가 끝날 때까지 아무 행동도 하지 않은 플레이어는 서버에서 자동 경매 포기로 처리합니다.
disconnect 상태에서도 서버 deadline은 계속 진행합니다.

## 4. 조기 종료

15초를 반드시 모두 기다리지 않습니다.
참가 확정 수 + 포기 확정 수가 투표 대상 수와 같아지면 즉시 투표를 종료합니다.

따라서 모든 플레이어 참가, 1명 참가 + 나머지 전원 포기, 2명 참가 + 나머지 전원 포기, 전원 포기 모두 즉시 종료됩니다.
누군가 미응답 상태면 deadline까지 기다립니다.

## 5. 투표 종료 결과

### 5.1 참가자 0명
- 경매를 열지 않음
- 도시는 미소유 유지
- 턴 종료 흐름으로 이동

### 5.2 참가자 1명
- 경쟁 입찰 UI를 열지 않음
- 유일한 참가자가 시작 경매가로 자동 매입
- 골드 차감과 소유권 이전을 서버에서 원자적으로 처리
- 기존 PROPERTY_BOUGHT 구매/코인 presentation 재사용
- 매입자에게 구매 성공 결과 표시
- 경매 종료

### 5.3 참가자 2명 이상
즉시 경쟁 경매를 시작합니다.

## 6. 참가 순서와 첫 입찰

경매 참가 선택이 서버에서 확정된 순서가 그대로 경매 입찰 순서입니다.

- 첫 번째 참가자 = 시작 경매가의 자동 첫 입찰자
- 두 번째 참가자 = 첫 수동 입찰 차례
- 이후 참가 확정 순서대로 순환
- 현재 최고 입찰자는 자신의 가격을 다시 올릴 필요가 없으므로 순환에서 건너뜀

여러 참가 요청이 거의 동시에 도착해도 클라이언트 timestamp를 사용하지 않습니다.
서버 row lock 안에서 실제로 확정된 순서를 authoritative 참가/입찰 순서로 사용합니다.
다른 플레이어의 투표 때문에 client version이 이미 증가했더라도 현재 상태가 동일한 AUCTION_VOTE이고 해당 플레이어가 아직 미결정이라면 유효 투표를 서버가 흡수합니다.

## 7. 경쟁 경매 규칙

- 첫 참가자가 시작가로 자동 첫 입찰
- 각 수동 입찰 차례 제한시간 10초
- 자신의 차례에 입찰 또는 포기
- 10초 무응답 = 자동 포기
- 한번 포기하면 해당 경매 재참여 불가
- 다음 최소 유효 입찰가 = 현재 최고가 + 1
- 다음 최소 유효 입찰가를 감당할 수 없으면 자동 포기
- 마지막으로 남은 최고 입찰자가 낙찰

## 8. 경매 참가 모달

Marble의 도시 정보 모달과 통행료 모달의 공통 시각 언어를 재사용합니다.
투표 단계에서 모달은 경매 단계 배지, 도시명, 남은 시간, 시작 경매가, 내 보유 골드, 경매 참가자 카드, 참가/포기/대기 인원 요약, 참가/포기 버튼, 미응답 자동 포기 안내를 보여줍니다.

### 8.1 경매 참가자 카드

참가 버튼이 서버에서 확정되는 순간 모든 플레이어에게 실시간으로 참가자 명단을 표시합니다.
표시 순서는 authoritative 참가 순서입니다.

예:

1. 플레이어 B · 첫 입찰
2. 플레이어 D
3. 플레이어 C

첫 참가자에게 ‘첫 입찰’ 배지를 표시하여 시작가 자동 입찰자임을 명확히 합니다.
도시 구매 포기자는 투표 조작 버튼을 보지 않고 진행 상태만 읽을 수 있습니다.

## 9. Realtime / reconnect

서버 state와 deadline을 authoritative 기준으로 사용합니다.
재접속 시 현재 경매 단계, 참가 확정자와 순서, 포기 확정자, 남은 투표 deadline, 경쟁 경매 참가자/입찰 순서, 현재 최고가/최고 입찰자, 현재 입찰 차례와 deadline을 snapshot에서 복구합니다.
로컬 기기 시계가 아니라 snapshot의 서버 시각을 기준으로 countdown을 표시합니다.

## 10. 서버 안전성

- expected_version
- client_action_id replay/idempotency
- 게임 row lock 기반 동시성 직렬화
- Realtime 이후 authoritative snapshot 수렴
- stale snapshot 방어
- 서버에서 골드/소유권 최종 검증
- legacy end-turn으로 경매 우회 불가

단, 참가 투표는 여러 플레이어가 동시에 결정하는 단계이므로 다른 플레이어의 투표로 발생한 stale version을 단순 실패시키지 않고 현재 vote가 동일하게 열려 있고 actor가 미결정인 경우 서버에서 순차 확정합니다.

## 11. Acceptance Criteria

1. 구매 포기 즉시 별도 요청 단계 없이 AUCTION_VOTE가 열린다.
2. 투표 제한시간은 15초다.
3. 구매 포기자는 투표 대상에서 제외된다.
4. 시작가를 감당하지 못하는 플레이어는 투표 대상에서 제외된다.
5. 참가와 포기는 플레이어당 단 한 번만 확정할 수 있다.
6. 참가 후 포기, 포기 후 참가가 불가능하다.
7. 모든 투표 대상이 결정하면 deadline 전이라도 즉시 종료한다.
8. 15초 미응답은 자동 포기 처리한다.
9. 참가 0명은 도시 미소유 상태로 종료한다.
10. 참가 1명은 150% 시작가로 즉시 자동 매입한다.
11. 참가 2명 이상은 즉시 경쟁 경매를 시작한다.
12. 첫 참가자가 시작가 자동 첫 입찰자다.
13. 참가 확정 순서가 입찰 순서다.
14. 모든 플레이어가 참가자 명단과 첫 입찰자를 확인할 수 있다.
15. 경쟁 경매의 수동 입찰 제한시간은 10초다.
16. 수동 입찰 무응답은 자동 포기한다.
17. 다음 최소 입찰가를 감당할 수 없으면 자동 포기한다.
18. disconnect/reconnect 후 서버 snapshot 기준으로 같은 상태에 수렴한다.
19. 정상 도시 구매 animation / coin movement를 자동 매입과 낙찰에 재사용한다.
