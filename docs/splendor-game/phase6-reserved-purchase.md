# Splendor Phase 6-2 — 예약 카드 구매

## 범위

이번 단계는 플레이어 본인이 예약해 둔 개발 카드 구매만 구현한다.

- 현재 턴 플레이어만 구매 가능
- 본인이 소유한 예약 카드만 구매 가능
- 공개 예약 / 덱 뒷면 예약 모두 동일하게 구매 가능
- 카드 원가에서 현재 영구 보너스를 뺀 실제 비용 계산
- 일반 보석 + Gold 와일드카드 결제
- 보유 일반 보석 대신 Gold를 사용하는 선택 지원
- 지불 토큰은 공급처로 반환
- 구매 카드 Prestige를 점수에 반영
- 구매 카드 색상의 영구 보너스 +1
- `reserved_card_count - 1`
- `purchased_card_count + 1`
- 정상 구매 후 다음 활성 플레이어에게 턴 이동
- expected_version + client_action_id 기반 동시성/중복 요청 방지

귀족 획득과 15점 종료 판정은 아직 이번 단계에 포함하지 않는다.

## 공개 카드 구매와 다른 점

예약 카드는 예약하는 순간 이미 공개 카드 자리 또는 덱에서 제거된 상태다.

따라서 예약 카드를 구매해도:

- 공개 카드 12장 구성은 바뀌지 않는다.
- 공개 슬롯을 새 카드로 보충하지 않는다.
- 덱 장수도 줄어들지 않는다.

대신 플레이어 상태에서:

```text
예약 카드 1장 감소
→ 구매 카드 1장 증가
→ 카드 점수 획득
→ 해당 색 영구 보너스 +1
→ 지불 토큰 공급처 반환
→ 다음 플레이어 턴
```

으로 진행된다.

## 서버 권한 검증

RPC:

```text
splendor_purchase_reserved(
  room_id,
  card_instance_id,
  payment,
  expected_version,
  client_action_id
)
```

서버는 클라이언트가 보낸 카드 ID와 결제를 그대로 신뢰하지 않는다.

1. 로그인 및 승인 회원인지 확인
2. 현재 방 멤버인지 확인
3. 진행 중 게임인지 확인
4. game version 확인
5. 현재 행동 단계가 `action`인지 확인
6. 요청자가 현재 턴인지 확인
7. 카드가 실제로 `reserved` 상태인지 확인
8. `owner_game_player_id`가 현재 요청자와 같은지 확인
9. 카드 비용과 플레이어 영구 보너스로 실제 비용 재계산
10. 일반 보석 지불량과 Gold 부족분 검증
11. 실제 보유 토큰 수량 검증
12. 전부 통과한 경우에만 한 트랜잭션으로 구매 처리

다른 플레이어가 예약한 카드 ID를 직접 RPC에 넣어도 `RESERVED_CARD_NOT_AVAILABLE`로 거부한다.

## Gold 결제

공개 카드 구매와 같은 규칙을 사용한다.

기본 UI는 일반 보석을 우선 사용하고 부족한 비용만 Gold로 채운다. 사용자가 일반 보석 대신 Gold를 사용하고 싶다면 결제 행의 `-` 버튼으로 일반 보석 결제량을 줄일 수 있다.

서버는 최종적으로 Gold가 할인 후 남은 비용과 정확히 일치하는지 다시 계산한다.

## 프론트 UI

- `내 예약 카드`의 카드 자체를 클릭하면 구매 결제 패널을 연다.
- 선택 카드에는 선택 상태를 표시한다.
- 결제 패널에서 정가 / 보너스 할인 / 실제 비용 / 보유 토큰 / Gold 사용량을 보여준다.
- 자신의 턴이 아니면 구매 버튼을 비활성화한다.
- 토큰이 부족하면 `보석이 부족합니다`를 표시한다.
- 구매 성공 후 예약 패널에서 해당 카드가 사라지고 예약 수가 1 감소한다.

- `splendor-game/css/phase6-reserved.css`
- `splendor-game/js/gameApi.js`

## 자동 검증 완료

모든 서버 행동 테스트는 `BEGIN ... ROLLBACK`으로 실제 게임 데이터를 보존했다.

### 성공 케이스

현재 테스트 계정의 예약 카드 `녹옥 교역소`를 구매 가능한 토큰 상태로 임시 조정한 뒤 구매:

- game version 22 → 23
- turn 18 → 19
- 현재 턴 seat 2 → seat 1
- 예약 카드 2 → 1
- 구매 카드 1 → 2
- 점수 1 → 2
- 초록 영구 보너스 +1
- 지불한 빨강 토큰 공급처 반환
- 카드 location `reserved` → `purchased`
- 공개 카드 수 12장 유지
- 전체 덱 장수 유지
- action log 1건 기록

같은 `client_action_id`를 두 번 전송해도 구매와 로그는 한 번만 적용됐다.

### 실패 케이스

- 상대 플레이어의 예약 카드 ID 구매 시도 → `RESERVED_CARD_NOT_AVAILABLE`
- 카드 실제 비용보다 부족한 결제 요청 → `PAYMENT_MISMATCH`
- 기존 공통 검증으로 내 턴 아님 / stale version / 보유 토큰 부족도 서버에서 거부

## 사용자 테스트 포인트

1. `내 예약 카드` 중 한 장 클릭
2. 예약 카드 구매 패널이 열리는지 확인
3. 정가 / 할인 / 실제 비용 / Gold 필요량 확인
4. 자원이 부족하면 구매 버튼이 비활성화되는지 확인
5. 자원을 모은 뒤 구매 버튼이 활성화되는지 확인
6. 구매 후 예약 목록에서 그 카드가 사라지는지 확인
7. 예약 수 -1 / 구매 카드 수 +1 확인
8. Prestige만큼 점수 증가 확인
9. 카드 색 영구 보너스 +1 확인
10. 지불 보석이 공급처로 돌아가는지 확인
11. 공개 카드와 덱 장수는 그대로인지 확인
12. 상대에게 턴이 이동하고 양쪽 화면이 동기화되는지 확인
13. 새로고침 후 상태 유지 확인
