# Splendor Phase 5-2 — 덱 맨 위 카드 비공개 예약

## 범위

Phase 5-2에서는 공개 카드를 선택하지 않고 특정 티어 덱의 맨 위 카드를 확인하지 않은 채 예약하는 기능을 연결한다.

카드 구매는 아직 포함하지 않는다.

포함 기능:

- 1/2/3단계 덱 중 하나 선택
- 선택한 티어의 맨 위 카드 1장 예약
- 예약 전에는 카드 정체를 확인할 수 없음
- 예약 완료 후 예약한 본인에게만 카드 상세 공개
- 상대에게는 예약 카드 장수만 공개
- 예약 카드 최대 3장
- 금 토큰이 남아 있으면 1개 지급
- 금 토큰이 없어도 예약 가능
- 금 지급으로 토큰이 10개를 넘으면 `return_excess` 단계
- 정상 종료 시 다음 플레이어로 턴 이동
- `game.version` 증가 및 기존 Realtime 동기화
- `client_action_id` 중복 요청 방지

## 공개 카드 예약과 차이

### 공개 카드 예약

- 공개된 카드 1장을 선택한다.
- 선택한 공개 카드가 예약 영역으로 이동한다.
- 비어 있는 공개 자리는 같은 티어 덱에서 즉시 보충한다.

### 덱 뒷면 예약

- 티어만 선택한다.
- 덱의 맨 위 카드를 보기 전에 예약한다.
- 공개 카드 4장은 그대로 유지된다.
- 선택한 티어의 덱 장수만 1장 감소한다.

## 서버 RPC

`public.splendor_reserve_hidden(room_id, tier, expected_version, client_action_id)`

서버에서 다음을 다시 검증한다.

1. 로그인 및 승인 회원 여부
2. 현재 방 참가자 여부
3. 진행 중 게임 여부
4. `expected_version`
5. 현재 턴 플레이어 여부
6. `turn_phase = action` 여부
7. 예약 카드 3장 제한
8. tier가 1/2/3인지
9. 선택한 티어 덱에 카드가 남아 있는지
10. 동일 `client_action_id`가 이미 처리됐는지

## 데이터 처리

선택한 티어에서 다음 조건의 카드 중 `deck_position`이 가장 작은 카드 1장을 선택한다.

```text
location = deck
order by deck_position
limit 1
```

예약 후 카드 인스턴스는 다음 상태가 된다.

```text
location = reserved
face_up_slot = null
owner_game_player_id = 현재 플레이어
reserved_hidden = true
```

`reserved_hidden = true`는 이 카드가 공개 카드가 아니라 덱 뒷면에서 예약된 카드임을 나타낸다.

## 비공개 정보

`private.splendor_game_snapshot()`은 예약 카드 상세를 소유자에게만 내려준다.

따라서:

- 예약한 플레이어: 카드의 비용, 보너스, 점수, 제목, `reserved_hidden` 확인 가능
- 상대 플레이어: 해당 카드의 상세 정보는 받지 않음
- 상대 플레이어: `reserved_card_count`만 확인 가능

## 자동 검증 결과

모든 테스트는 실제 진행 중 게임을 사용하되 `BEGIN ... ROLLBACK`으로 종료해 사용자 게임 상태를 보존했다.

### 정상 예약

- 1단계 덱: 6장 → 테스트 중 5장
- 공개 카드: 12장 유지
- 예약 카드 수: 1장 → 테스트 중 2장
- 플레이어 금 토큰: 0 → 1
- 공급처 금 토큰: 3 → 2
- 현재 턴: 좌석 1 → 좌석 2
- 게임 버전: 12 → 테스트 중 13
- 본인 Snapshot에서 `reserved_hidden = true` 카드 확인
- ROLLBACK 후 실제 상태는 버전 12 / 1단계 덱 6장 / hidden 예약 0장으로 복구

### 중복 요청

같은 `client_action_id`로 `splendor_reserve_hidden`을 두 번 호출했다.

정상 결과:

- action log 1건
- 덱 1장만 감소
- 예약 카드 1장만 증가
- 금 토큰 1개만 지급
- game version 1회만 증가

### 비공개 정보

소유자와 상대방 계정으로 각각 Snapshot을 조회했다.

정상 결과:

- 소유자 Snapshot: `reserved_hidden = true` 카드 1장 확인
- 상대 Snapshot: 해당 hidden 카드 상세 0장
- 상대 Snapshot의 플레이어 정보에는 예약 카드 장수만 증가해서 표시

### 차단 검증

- 현재 턴이 아닌 플레이어 → `NOT_YOUR_TURN`
- 선택한 티어 덱이 비어 있음 → `DECK_EMPTY`
- 잘못된 tier → `INVALID_TIER`
- 예약 카드 3장 이상 → `RESERVE_LIMIT_REACHED`

## 브라우저 테스트

현재 실제 테스트 게임은 이전 공개 카드 예약 테스트 직후 `return_excess` 상태일 수 있다.
먼저 화면에 초과 토큰 반환 안내가 보이면 필요한 토큰을 반환해 턴을 정상 종료한다.

그 후 다음을 확인한다.

1. 현재 턴 플레이어 화면에서 각 티어 제목 옆에 `🂠 덱에서 예약 · N장` 버튼이 보이는가?
2. 상대 플레이어 화면에서는 버튼이 비활성화되는가?
3. 현재 턴 플레이어가 원하는 티어의 `덱에서 예약` 버튼을 누를 수 있는가?
4. 공개 카드 4장은 그대로 유지되는가?
5. 선택한 티어의 `덱 N장` 표시만 1 감소하는가?
6. `내 예약 카드`에 새 카드가 나타나는가?
7. 새 예약 카드에 `덱 뒷면에서 예약` 표시가 보이는가?
8. 금 토큰이 남아 있으면 내 금 +1 / 공급처 금 -1이 되는가?
9. 토큰이 10개를 넘으면 턴이 넘어가기 전에 초과 토큰 반환을 요구하는가?
10. 상대방은 예약 장수 증가는 볼 수 있지만 카드 내용은 볼 수 없는가?
11. 새로고침 후에도 상태가 유지되는가?
