# Marble Auction — Playtest UX Review

업데이트 기준: 2026-09-18

이 문서는 Phase 7A Auction의 서버 권위 규칙을 다시 설계하는 문서가 아니라, **실제 플레이테스트에서 발견된 UI / 플레이 흐름 개선 요구를 정리하기 위한 후속 검토 문서**입니다.

## 현재 상태

Phase 7A의 다음 기반은 구현 완료 상태입니다.

- 구매 거절 후 auction request
- eligible player 계산
- 입찰 / 패스
- 낙찰 / 유찰
- authoritative RPC
- expected_version / client_action_id
- Realtime / reconnect
- stale snapshot 방어
- 온라인 경매 UI

따라서 이번 재검토의 기본 방향은 **검증된 서버 권위와 동기화 계약을 최대한 유지하면서 UX를 개선하는 것**입니다.

## 플레이테스트 피드백

2026-09-18 실제 플레이 기준으로 현재 경매 시스템은 기능적으로 동작하지만 **UI와 전체 진행 흐름을 다시 다듬을 필요가 있음**을 확인했습니다.

2026-09-18 추가 플레이테스트 논의에서 Auction v2의 핵심 흐름과 시작가 규칙을 요구사항으로 확정하기 시작했습니다.

현재 확정된 v2 요구사항과 미확정 예외 항목은 [Marble Auction v2 Requirements](./marble-auction-v2-requirements.md)를 기준으로 관리합니다.

## 요구사항 정의 시 확인할 항목

### 1. 경매 진입

- 구매 거절 직후 경매가 시작되는 맥락이 충분히 이해되는가
- `AUCTION_REQUEST` 단계를 사용자에게 어떻게 설명할 것인가
- 요청 가능한 플레이어와 불가능한 플레이어가 명확한가
- 경매를 요청하지 않는 경우의 종료 흐름이 자연스러운가

### 2. 경매 화면 정보 계층

항상 보여야 할 후보:
- 대상 도시
- 도시 정가
- 현재 최고 입찰가
- 다음 최소 입찰가
- 내 보유 골드
- 현재 최고 입찰자
- 참가자 상태

필요 시 보여줄 후보:
- 해당 도시 건설 정보
- 예상 통행료
- 지역 / 독점 진행도

### 3. 입찰 조작

검토 대상:
- 직접 숫자 입력
- +/- 증감
- 빠른 증가 버튼
- 최소 입찰가 자동 채움
- 최대 보유 골드 제한 표현
- 실수 입찰 방지

### 4. 패스

- 패스의 의미를 명확히 설명할 것
- 패스 후 재참여 불가 상태 표시
- 최고 입찰자는 패스할 수 없다는 규칙을 UI로 자연스럽게 설명할 것

### 5. 참가자 진행 상태

사용자가 즉시 이해할 수 있어야 하는 정보:
- 아직 행동하지 않은 플레이어
- 입찰한 플레이어
- 패스한 플레이어
- 현재 최고 입찰자
- 경매에 참여할 수 없는 플레이어

### 6. 종료

- 낙찰 조건을 사용자가 이해할 수 있어야 함
- 유찰 조건을 사용자가 이해할 수 있어야 함
- 결과 직후 소유권 / 골드 변화가 시각적으로 연결되어야 함
- 경매 종료 후 원래 턴 흐름으로 자연스럽게 복귀해야 함

### 7. 게임 템포

검토 질문:
- 경매 요청 단계가 너무 많은 클릭을 만드는가
- 여러 플레이어의 응답 때문에 게임이 과도하게 정지되는가
- timer / deadline이 필요한가
- 자동 처리 가능한 부분이 있는가
- 플레이어 선택권을 유지하면서 단계 수를 줄일 수 있는가

### 8. 모바일

- 작은 화면에서 도시 정보와 입찰 UI가 동시에 읽히는가
- 숫자 입력이 불편하지 않은가
- 주요 버튼이 엄지 조작 범위에 있는가
- 키보드가 보드를 과도하게 가리지 않는가

### 9. Presentation

후보:
- 경매 시작 강조
- 입찰 금액 변화
- 새로운 최고 입찰자 강조
- 패스 상태 전환
- 최종 낙찰
- 유찰
- 소유권 색상 전환

## 변경 안전 경계

요구사항 확정 전에는 다음을 임의로 변경하지 않습니다.

- 서버 authoritative ownership settlement
- expected_version 계약
- client_action_id replay / idempotency
- Realtime snapshot refresh
- 구매 거절자의 경매 참여 제외 규칙
- eligible player / bankruptcy guard

규칙 자체를 변경해야 한다는 플레이테스트 요구가 확인되면 UX 수정과 분리하여 별도로 결정합니다.

## 현재 분류 결과

Auction v2 요구사항은 다음 세 범주를 모두 포함합니다.

- UI 수정
- 플레이 흐름 수정
- 게임 규칙 수정

구체적인 확정 규칙과 미확정 예외는 [Marble Auction v2 Requirements](./marble-auction-v2-requirements.md)를 기준으로 합니다.

실제 구현은 해당 문서의 미확정 제품 규칙을 먼저 확정한 뒤 별도 작업 브랜치에서 시작합니다.
