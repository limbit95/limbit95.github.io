# Fruit Bell 3D prototype

현실에서 카드를 넘기고 종을 치는 감각을 웹에서 최대한 살리는 1인칭 3D 카드게임 프로토타입입니다.

## 현재 구현 범위

- Three.js WebGL 기반 3D 테이블/종/카드
- 높은 1인칭 카메라와 축소된 중앙 종으로 맞은편 공개 카드 판독성 확보
- 선택한 동물 색을 반영한 1인칭 오른손/왼팔
- 상대 3명의 절차적 3D 동물 아바타
- 카드 더미에서 `좌클릭 유지 → 위로 드래그`해야 카드가 뒤집히는 제스처
- 카드가 손과 함께 테이블 앞으로 이동하며 공개되는 3D 플립 연출
- 카드 앞면은 공통 reveal gate 전까지 숨기고, reveal 시점부터 과일 HUD/종 입력을 동시에 활성화
- `Space` 입력 시 왼손이 중앙 종을 강타하는 연출
- 금속 데스크벨을 흉내 낸 합성 종소리 + 오답 전용 경고 효과음
- 보유 카드 수에 따라 실제 3D 카드덱 높이가 증감
- 정답 종을 친 플레이어에게 각 공개 카드 더미가 순차적으로 날아가 쌓이는 수거 애니메이션
- 과일 합계가 정확히 5인지 판정하는 룰 엔진
- 봇의 카드 뒤집기/종 반응 애니메이션
- 마우스 위치에 따른 1인칭 카메라 시선 이동

## 카드 공개 공정성

현재 프로토타입은 한 브라우저 안에서 봇과 플레이하므로 실제 네트워크 지연을 재현하지는 않습니다. 대신 멀티플레이에서 그대로 사용할 수 있도록 **카드 내용이 보이는 시점(reveal)** 을 카드 생성/상태 갱신과 분리했습니다.

- 플립 시작 직후 상태 문구나 HUD에서 과일 정보를 먼저 노출하지 않습니다.
- 공통 reveal 시점 전에는 움직이는 카드의 과일 면도 숨깁니다.
- reveal 시점에 카드 앞면, 과일 합계 HUD, 종 입력/봇 반응을 같은 게이트에서 엽니다.
- 실제 Supabase 멀티플레이에서는 서버가 충분히 미래의 `reveal_at`을 정하고 모든 참가자에게 동일하게 전송한 뒤, 각 클라이언트가 서버 시계 오프셋을 보정해 그 시각에만 공개하도록 연결할 예정입니다.
- 종 선착순 판정 역시 서버의 authoritative 판정과 결합해야 실제 사용자 간 공정성을 완성할 수 있습니다.

## 의도적으로 제외한 범위

이번 단계는 3D 체감 확인을 위한 프로토타입이므로 아래는 후속 작업으로 남겨둡니다.

- Supabase Realtime 멀티플레이
- 네트워크 지연을 고려한 종 선착순 authoritative 판정
- Zoom 또는 화상회의 연동 (게임에서는 연동하지 않음)
- 정식 GLTF 리깅 동물 모델
- 표정/감정/이모트 시스템
- 사용자별 아바타 저장

## 확장 방향

게임 규칙(`gameEngine.js`)과 3D 표현(`scene.js`, `avatarFactory.js`)을 분리했습니다. 이후 절차적 동물 모델을 GLTF 리깅 모델로 교체하더라도 카드 플립/종 치기 이벤트를 동일하게 유지할 수 있도록 구성합니다.

카메라의 눈높이, FOV, 시선 범위, 상체 기울임과 종 타격 반응은 presentation 계층에서 계속 조정할 수 있어 정식 모델 이후에도 재설계가 가능합니다.

향후 아바타 동작은 `idle`, `look`, `flip-card`, `ring-bell`, `celebrate`, `miss`, `emote` 등 공통 액션으로 확장하고, 각 동물 모델이 같은 액션 계약을 구현하는 방향을 권장합니다.
