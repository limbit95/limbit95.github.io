# Marble Worlds

테마마다 다른 세계관과 규칙을 선택해 즐기는 온라인 마블 보드게임 모듈입니다.

## 현재 개발 단계

`Phase 4 — 2.5D Visual Foundation`

Classic 핵심 규칙과 32칸 보드 구조는 유지하면서, 자유 시점 3D가 아닌 **고정 쿼터뷰의 밝은 미니어처 도시형 2.5D 플레이 화면**을 정식 시각 기반으로 다듬는 단계입니다.

현재 구현 범위:

- Classic / Space / Ocean / Fantasy 테마 선택 로비
- Theme Registry
- 방향/분기 이동을 지원하는 Board Graph
- Turn State Machine과 공통 Action 구조
- **32칸 Classic 세계일주 보드**
- 2주사위 / 이동 경로 / 출발점 보너스
- 도시 구매 / 소유권 / 최대 3단계 건설
- 단계별 통행료 / 자금 이동
- 지원금 / 세금 / 이벤트 / 휴식
- 휴식 턴 스킵
- 파산 / 소유지 반환 / 마지막 생존자 승리
- `lastEvents`와 `PLAYER_MOVED.path`
- Game Engine과 Renderer 분리
- Classic 2인 로컬 수동 플레이테스트
- 데스크톱 전용 플레이 창과 모바일 same-tab fallback
- Three.js 기반 고정 Orthographic 쿼터뷰
- 사용자 자유 회전/줌 제거
- 32칸 외곽 보드와 한글 도시 라벨
- **밝은 장난감 도시 팔레트**
- **도시별 미니 랜드마크 아키타입**
- **START / EVENT / TAX / BONUS / REST 전용 미니 오브젝트**
- **장난감형 플레이어 캐릭터 말**
- **1~3단계 건설 실루엣 차등화**
- 중앙 공원 / 수로 / 미니 스카이라인 / 글로브 디오라마
- 현재 플레이어 하이라이트
- 타일 클릭/터치 선택
- 3D 로드 실패 시 2D 상태 보드 유지
- 30~40칸 규모 레이아웃 테스트

## 시각 방향 원칙

최종 목표는 특정 상용 게임의 에셋이나 UI를 복제하는 것이 아니라, 다음과 같은 **밝고 화려한 캐주얼 2.5D 보드게임 감각**을 자체 디자인으로 구현하는 것입니다.

```text
내부 구현
Three.js 3D 오브젝트 / 조명 / 그림자
        ↓
플레이 경험
고정 쿼터뷰 / 2.5D / 장난감 도시 디오라마
```

플레이어는 보드를 자유롭게 회전하지 않습니다. 카메라는 게임이 정한 시점을 유지하고, 향후 턴 이동·건설·이벤트 등 필요한 순간에만 짧은 자동 연출을 추가합니다.

Classic 비주얼은 다음 원칙을 사용합니다.

- 어두운 기술 데모보다 밝은 하늘과 선명한 지역 색상
- 각 도시가 이름뿐 아니라 작은 랜드마크 실루엣으로 구분
- 구매 후 건설 단계가 올라갈수록 건물 존재감이 커짐
- 플레이어 말은 단순 원기둥이 아니라 캐릭터형 미니어처
- 중앙 공간도 빈 판이 아니라 작은 세계처럼 구성
- 게임 규칙과 애니메이션 결과는 계속 Engine의 authoritative state를 따름

## Classic 보드 규모 원칙

최종 Classic 보드는 **30칸 이상**을 유지합니다.

현재 보드는 32칸이며, 자동 테스트에서 40칸까지 위치 중복 없이 확장 가능한 레이아웃을 검증합니다.

## 브라우저에서 수동 테스트

`marble-game/`에서 Classic을 선택하고 **Classic 플레이 창 열기**를 누릅니다.

이번 단계에서는 규칙 자체보다 아래 시각 요소를 우선 확인합니다.

1. 32칸 전체가 고정 쿼터뷰에서 한눈에 들어오는지
2. 화면이 자유 카메라 3D가 아니라 안정적인 2.5D 게임 화면처럼 느껴지는지
3. 도시별 랜드마크가 서로 다른 실루엣으로 읽히는지
4. 특수 칸이 일반 도시와 시각적으로 구분되는지
5. 플레이어 A/B가 캐릭터형 말로 보이고 같은 칸에서도 구분되는지
6. 현재 플레이어 표시가 자연스러운지
7. 주사위 후 캐릭터가 칸 단위로 뛰어 이동하는지
8. 구매/건설 후 건물 단계가 1 → 2 → 3으로 시각적으로 커지는지
9. 타일 클릭/터치가 기존처럼 동작하는지
10. 필요하면 2D 상태 보드와 Engine 상태가 일치하는지

현재 주사위는 로컬 브라우저 테스트용 `Math.random`을 사용합니다. 온라인 멀티플레이 단계에서는 서버 RPC가 authoritative 결과를 확정합니다.

## 3D 기술

Three.js 브라우저 ES Module 버전은 고정합니다.

```text
three@0.185.1
```

`threeClassicPrototype.js`는 `mount()` 시점에 Three.js를 동적으로 불러오기 때문에 Node 기반 게임 규칙 테스트는 WebGL이나 DOM 없이 실행할 수 있습니다.

순수 함수로 다음을 자동 검증합니다.

- `CLASSIC_CAMERA_PROFILE`
- `CLASSIC_VISUAL_PROFILE`
- 32칸 / 40칸 보드 레이아웃
- 고정 Orthographic framing
- 지역별 타일 색상
- 도시 랜드마크 아키타입
- 특수 타일 전용 오브젝트 매핑

## 핵심 설계 원칙

1. 게임 규칙은 DOM이나 Three.js를 직접 참조하지 않습니다.
2. 보드는 Node/Edge 그래프로 유지합니다.
3. Theme은 공통 Engine에 등록되는 모듈입니다.
4. Renderer는 확정된 Game State와 이벤트를 표현만 합니다.
5. 말 이동은 `PLAYER_MOVED.path`를 읽으며 애니메이션이 게임 결과를 결정하지 않습니다.
6. 수동 테스트 UI도 실제 Engine Action을 사용합니다.
7. 온라인 단계에서는 서버 RPC가 authoritative state를 갱신합니다.
8. `prefers-reduced-motion` 사용자는 말 이동을 즉시 반영합니다.
9. 플레이어 자유 카메라 조작은 제공하지 않습니다.
10. 상용 게임의 실제 그래픽 에셋이나 UI를 복제하지 않고 자체 미니어처 비주얼 시스템을 사용합니다.
